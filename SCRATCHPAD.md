# Portfolio — Document d'orientation

> Document de cadrage.
>
> Ce document définit le rôle du portfolio, son public, son message, sa structure et les principes qui guideront sa conception.

---

# 1. Objectif

Le portfolio n'a pas vocation à vendre une prestation commerciale.

Le portfolio a pour objectif de présenter un profil professionnel atypique à un employeur potentiel.

L'objectif n'est pas de convaincre tous les recruteurs.

L'objectif est d'identifier les structures capables de reconnaître la valeur d'un profil transversal.

Le portfolio doit permettre au visiteur de répondre rapidement à une question :

> Dans quel contexte ce profil peut-il apporter le plus de valeur ?

---

# 2. Positionnement

Le portfolio ne présente pas un spécialiste.

Il présente un profil capable d'intervenir à différentes étapes du cycle de vie d'un produit.

Le positionnement repose sur quatre verbes.

- Analyser
- Construire
- Coordonner
- Accompagner

Les technologies ne constituent pas l'identité principale du profil.

Le cœur du message est le suivant :

> Comprendre un système dans sa globalité afin de concevoir des solutions cohérentes.

---

# 3. Les deux contextes d'intervention

## Construire

Contexte :

- TPE
- PME
- Produits internes
- Applications métiers
- Outils spécialisés

Valeur apportée :

- Analyse du besoin
- Conception
- Développement
- Intégration
- Déploiement

Message :

> Transformer une idée en produit.

---

## Coordonner

Contexte :

- Équipes pluridisciplinaires
- Produits plus complexes
- Projets impliquant plusieurs domaines d'expertise

Valeur apportée :

- Architecture globale
- Communication entre les domaines
- Arbitrage
- Cohérence technique
- Vision d'ensemble

Message :

> Faire converger plusieurs expertises vers une architecture commune.

---

# 4. Ce qui est démontré

Le portfolio doit s'appuyer sur des preuves concrètes.

Les réalisations doivent démontrer :

- La conception d'un système
- La capacité à relier plusieurs couches techniques
- La transformation d'un besoin en solution
- La capacité à passer d'une idée à un produit fonctionnel

Les preuves reposent sur les systèmes présentés.

---

# 5. Ce qui n'est pas encore démontré

Le portfolio ne doit pas prétendre démontrer :

- La gestion d'une infrastructure à très grande échelle
- La résistance sous forte charge
- La direction d'équipes importantes
- Les audits de sécurité avancés
- L'exploitation de systèmes complexes sur plusieurs années

Ces éléments doivent être identifiés comme des expériences à acquérir et non comme des compétences déjà validées.

---

# 6. Philosophie de présentation

Le portfolio ne doit pas ressembler :

- À un CV
- À une galerie d'images
- À une démonstration technique
- À un portfolio Three.js spectaculaire

Le portfolio doit raconter une histoire.

Chaque projet doit être présenté sous la forme d'une étude de cas.

Structure recommandée :

- Le problème
- Le contexte
- Les contraintes
- Les choix réalisés
- L'architecture
- Le résultat

---

---

# 8. Modèle de navigation

## Navigation horizontale

Chaque section représente un chapitre.

Le défilement horizontal permet de passer d'un chapitre à un autre.

---

## Navigation verticale

Chaque chapitre peut être parcouru verticalement.

Les projets utilisent le défilement vertical pour détailler :

- Le besoin
- La conception
- Les contraintes
- L'architecture
- Les résultats

---

## Navigation fixe

### En-tête

L'en-tête ne contient pas le menu.

Il affiche uniquement :

- Nom
- Logo ou photo
- Nom du site
- Section courante

---

### Barre inférieure

Le menu principal est positionné en bas.

Objectifs :

- Navigation rapide
- Accès direct à chaque section
- Visualisation de la progression dans le parcours

---

# 9. Principes UX

Le portfolio doit être :

- Original
- Immédiatement compréhensible
- Accessible
- Rapide à parcourir

L'interface ne doit jamais devenir le sujet principal.

Le contenu reste prioritaire.

Règle fondamentale :

> L'originalité doit servir la lecture.

---

# 10. Message implicite

Le portfolio ne doit jamais chercher à démontrer :

> Je suis le meilleur spécialiste.

Le portfolio doit démontrer :

> Je comprends suffisamment chaque couche d'un système pour concevoir une solution cohérente.

---

# 11. Message final

Le visiteur doit quitter le site avec une idée simple :

> Ce profil n'est peut-être pas celui que j'étais venu chercher.

> Mais c'est peut-être exactement celui dont mon projet a besoin.

---

# 12. Citation à conserver

À ne pas utiliser comme titre principal.

À conserver comme signature potentielle.

> Le développeur dont vous pensiez ne pas avoir besoin et dont vous ne pourrez plus vous passer.
